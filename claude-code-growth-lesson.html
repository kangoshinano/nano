同じミスを繰り返さないClaude Codeの育て方

Claude Codeを使い始めた人から多いのが「毎回同じところでミスをする」「すぐ使えなくなる（使用制限）」「パソコンの中を全部見られるのが怖い」という相談です。このレッスンでは、Claude Codeを安心して長く使うためのコツをまとめます。

図解：同じミスを繰り返さない育て方

  1. 部屋を分けるメルマガ用・LINE用など、用途ごとにチャットを分ける
  2. ひな形を渡すうまくいった前回分を、見本として読ませる
  3. スキル化する「これをスキルにして」で、手順を保存させる
  4. 一覧で確認「スキルを一覧で出して」で、何を覚えたか確かめる
チャットは閉じると忘れる。覚えてほしいことは必ずスキルにする

0. 知っておく前提：Claude Codeの「記憶」は3種類

Claude Codeは、チャットを新しくすると、前のやり取りを覚えていません。「前に言ったのに」が起きるのはこのためです。覚えさせたいことは、置き場所を選んで保存します。

チャット（会話）閉じると忘れる。その場の指示・修正はここ。長くなると、序盤の指示を忘れやすくなります。
CLAUDE.md毎回読み込まれる、常設のメモ。「いつも守ってほしい短いルール」（呼び方、署名、禁止事項など）を書きます。長くしすぎると、かえって負担になります。
スキル手順書。「メルマガの書き方」「LINE配信の型」など、作業ごとの手順を保存します。必要なときだけ読まれます。
使い分けの目安
「どの作業でも常に守ってほしい」→ CLAUDE.md／「この作業のときだけ使う手順」→ スキル／「今回だけの指示」→ チャット

1. 毎回同じミスをするときは「スキル化」

たとえば、メルマガやLINEの下書きを作ってもらうたびに、次のようなミスが繰り返されることがあります。

  • 画像が中央ではなく左寄せになる
  • 入れてと言った文章が入っていない

そこで、絶対に覚えておいてほしいことは「スキル化して」と指示して、手順として保存させます。

  • メルマガのライティングのルール
  • LINE配信の型
  • 画像の配置や、必ず入れる署名

用途ごとに1つずつスキルにまとめておくと、次からはそのスキルを読んで作業してくれます。

スキルの仕組み（ちょっとだけ）

  • スキルは、フォルダの中のSKILL.mdという1つのファイルです。上に「名前（name）」と「いつ使うか（description）」、その下に「手順」を書きます。
  • 置き場所は2種類あります。自分用（全部のプロジェクトで使える）と、プロジェクト用（そのフォルダの中だけで使える）です。
  • Claude Codeは、最初に各スキルの名前と説明だけを読み、作業に合うと判断したときに中身を読みます。そのため、「何をするスキルか」と「いつ使うか」を、説明にはっきり書くことが大切です。

スキル化の手順

  1. うまくいった作業を1つ選ぶメルマガ1通、LINE配信1本など
  2. 「これをスキルにして」と頼むミスの修正内容（左寄せNG、署名必須など）も伝える
  3. 名前と使う場面を確認する「いつ使うスキルか」が1行で言えるか
  4. 次の作業で使ってみる新しいチャットで、スキルを使って作らせる
  5. ミスが出たら、スキルに追記する「今のミスを、スキルに書き足して」
📋 コピー用：今の作業をスキルにする
今やった作業を、あとで毎回同じ品質で再現できるように「スキル」として保存してください。

スキルの名前：【例：メルマガ作成】
いつ使うか：【例：メルマガの下書きを作ってと頼まれたとき】

必ず入れてほしい内容：
・手順（どの順番で何をするか）
・今回のやり取りで私が直した点（同じミスを繰り返さないための注意）
　例：画像は中央寄せにする／冒頭にお名前の差し込みを入れる／最後に署名を必ず入れる
・出力の形（見出し、文字数の目安、口調）
・やってはいけないこと

保存したら、スキルの名前と、保存した場所を教えてください。
📋 コピー用：ミスをスキルに書き足す
いまのミスを、二度と繰り返さないように、【スキル名】に注意点として書き足してください。

今回のミス：【例：画像が左寄せになっていた。中央寄せにするのが正しい】

書き足したあと、スキルの該当部分を見せてください。

何をスキルにしたかは、一覧で確認

何をスキルにしたかは、自分でも忘れがちです。「私のスキルを一覧で出して」と聞くと、保存されているスキルがまとめて表示されます。名前と説明を見て、重複や古いものがないか、ときどき整理しましょう。

スキルにするとよい作業の目安

同じ指示を何度も出している貼り付けるたびに同じ説明をしているなら、スキルにする
同じミスが2回出た3回目を起こさないために、スキルに注意点を足す
手順が決まっている作業メルマガ、LINE配信、台本作成、集計、レポート作成など
他の人に引き継げそうな作業スキルの形にしておくと、手順書にもなる

※スキルの作り方や置き場所は、Claude Codeの更新で変わることがあります。うまくいかないときは、公式ドキュメント（code.claude.com の Skills のページ）で確認してください。

2. チャットは用途ごとに「部屋」を分ける

1つのチャットで何でもやると、話が混ざって精度が落ちます。メルマガ用、LINE用、分析用のように、用途ごとにチャット（部屋）を分けて使いましょう。

うまくいった前回の作業がある場合は、それをひな形として渡すと、同じ形で作ってくれます。Claude Code自身も「前回のものをひな形として渡してもらえると精度が上がる」と答えてくれます。

部屋の分け方の例

メルマガの部屋下書き作成、件名案、チェック
LINEの部屋配信文、シナリオの作成
分析の部屋数値の集計、比較
相談の部屋企画の壁打ち、アイデア出し

会話が長くなったとき

/clear会話をリセットして、別の作業を始めるとき。前の会話は引き継がれません。
/compact同じ作業を続けたいけれど、会話が長くなったとき。それまでの会話を要約して、続きを進めます。
  • 会話が長くなると、序盤に伝えた指示を忘れやすくなります。長引いたら、残したい内容を整理してから新しい部屋で再開するのがおすすめです。
  • 途中までの結果は、ファイルに保存しておくと、新しい部屋でも「このファイルを読んで続きを」と頼めます。

※コマンドの名前や挙動は、Claude Codeの更新で変わることがあります。

3. 使用制限とモデルの使い分け

使用量には上限がある一気に使い切ると、一定時間（目安5時間）使えなくなります。
対策：使用状況の画面で残量を確認しながら、まとめて指示を出す → 休むのリズムで使う
週ごとの上限もある5時間の枠とは別に、1週間単位の上限もあります。5時間たっても、週の上限に達していると使えないことがあります。
上位モデルほど使用量の減りが早い対策：スキルやルーティン作業の最初の仕組み作りだけ上位モデル、毎日の作業は標準モデルで回す

使用量を節約するコツ

  • 指示はまとめて出す：細かく何度もやり取りするより、条件を揃えて1回で頼む
  • 会話を長引かせない：長い会話は、毎回それまでの内容を読み直すため、使用量が増えやすい
  • 簡単な作業は標準モデルで：誤字チェック、整形、定型の作業など
  • スキルを整える：毎回の説明を省けるうえ、やり直しが減る
  • 大きなファイルを丸ごと読ませない：必要な部分だけ渡す

※プランごとの上限や、確認用の画面・コマンドは、変更されることがあります。最新の内容は、Claudeの公式ヘルプとアカウントの使用状況画面で確認してください。

4. 安全に使うためのルール

最初に決めておきたい3つのルール
Claude Codeは、許可するとパソコンの中のファイルを読んだり、ブラウザを操作したりできます。便利な反面、最初にルールを決めておくことが大切です。
  1. 課金とパスワードのルールを覚えさせる「課金はしない」「パスワードは覚えない」と、最初にルールとして覚えさせる
  2. 読ませたくないものは、専用フォルダへAPIキーやパスワードなど、絶対に読ませたくないものは専用のフォルダ（シークレットフォルダ）に入れて、「このフォルダは読まない」とルールにしておく
  3. お金に直結するサービスにはつながない会計ソフト、ネットバンキング、決済の管理画面など

パソコン自体のウイルス対策も、あわせてしっかりしておきましょう。

「お願い」より強い「禁止」の設定

「読まないで」とお願い（CLAUDE.mdやチャット）するだけでは、必ず守られる保証はありません。絶対に読ませたくないファイルは、設定で「禁止（deny）」にしておくとより安全です。

お願い（ルールを書く）CLAUDE.mdやチャットで「このフォルダは読まない」と伝える。強制力はないので、補助として使う。
禁止（設定ファイル）設定ファイルに「このファイルは読めない」と書く。Claude Codeの仕組みとして止める。
📋 設定ファイルの書き方の例（プロジェクトの .claude/settings.json）
{
  "permissions": {
    "deny": [
      "Read(./.env)",
      "Read(./.env.*)",
      "Read(./secrets/**)"
    ]
  }
}
  • 上の例は、「.env」や「secrets」フォルダの中身を読ませない設定です。フォルダ名は、自分の環境に合わせて書き換えます。
  • 設定したら、実際にそのファイルを読ませようとして、止まることを確認します。書き方を間違えると、効かないことがあります。
  • ファイルの読み取りを止めても、別の方法（コマンドの実行など）で中身が見えてしまう場合があります。そもそも大事な情報は、作業フォルダの外に置くのが一番確実です。
  • 設定ファイルの書き方に自信がなければ、Claude Codeに「このフォルダを読めないように設定して。設定後、読めないことをテストして」と頼むのも手です。

許可の確認は、読み飛ばさない

  • Claude Codeが「このコマンドを実行してよいか」と聞いてきたときは、内容を読んでから許可する
  • 「ファイルを消す」「外部に送る」「お金に関わる」操作は、特に慎重に
  • 大事なファイルは、作業前にバックアップを取っておく
  • 作業するフォルダを、専用の場所に限定する（パソコン全体を作業場にしない）

5. SNSの自動投稿は「下書き保存」までが安心

Threadsなどの投稿を完全に自動化すると、AIが想定外の動きをしたときに1日に大量に投稿してしまい、アカウントが停止されたという例もあります。

✕ 完全自動
  • AIが考えて、AIが投稿ボタンまで押す
  • 想定外の動きに、気づけない
  • アカウント停止のリスク
◯ 下書きまでAI
  • 「毎朝9時に下書き保存しておいて」までをAIに任せる
  • 投稿ボタンは自分で押す
  • 内容・リンク・日時を、目で見て確認できる

少し手間は残りますが、アカウントを失うリスクに比べればずっと安全です。

配信・投稿は「公開前に自分の目で確認」
UTAGEなどの配信設定をClaude Codeに任せる場合も、日時・対象・リンク・本文、そして予定していた配信が全部入っているかを、公開前に確認しましょう（「肝は自分、雑務はAI」のレッスンも参照）。

よくある失敗と対策

毎回、同じところでミスをするスキルに注意点を書き足す。ひな形（うまくいった前回分）を渡す
前に言ったことを覚えていないチャットは閉じると忘れる。常に守ってほしいことはCLAUDE.md、作業の手順はスキルへ
話が混ざって、精度が落ちた用途ごとに部屋を分ける。長くなったら整理して新しい部屋で再開する
すぐ使えなくなるまとめて指示を出す。上位モデルは仕組み作りだけに使う
大事な情報を読まれないか不安シークレットフォルダに分け、設定ファイルで禁止にする。テストして確認する
SNSの自動投稿でトラブル下書き保存までをAIに任せ、投稿は自分で押す
✏ ワーク　あなたのClaude Codeを育てる
  1. 最近、Claude Codeが繰り返したミスを2つ書き出す
  2. そのミスが起きた作業を1つ選び、「これをスキルにして」と頼む（ミスの内容も伝える）
  3. 新しいチャットで、そのスキルを使って同じ作業をさせてみる
  4. 「私のスキルを一覧で出して」と頼み、名前と説明を確認する
  5. 「課金はしない」「パスワードは覚えない」「このフォルダは読まない」の3つのルールを、最初のチャットで伝える
まとめ 覚えてほしいことはスキルにして、「スキルを一覧で出して」で確認する。チャットは用途ごとに分け、うまくいった前回分をひな形として渡す。使用制限は「まとめて指示→休む」で付き合い、課金・パスワード・お金に関わるサービスには触らせないルールを最初に決めておきましょう。大事なファイルは設定で読めないようにして、実際にテストすると安心です。
